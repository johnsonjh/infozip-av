# Xtro-ZIP cu102: complete bitwiseworks OS/2 history audit

Basis: full `.git` histories from a user-supplied `zip-os2.tar.xz` (12 reachable commits, `d24b653` HEAD) and `unzip-os2.tar.xz` (15 reachable commits, `2c13f24` HEAD). Both were inspected with `git show`, including changed-file lists and the operative code changes. The repos retain an old Info-ZIP Zip 3.0 / UnZip 6.0 base. They are *not* compatible replacement source trees for Xtro-ZIP cu102. Decisions below target cu102 and native Open Watcom V2 (`wcc386`, `wlink system os2v2`, no kLIBC/libcx).

Status legend: **PORT** = included in the accompanying incremental OS/2 patch; **EXISTING** = cu102 already has the relevant behavior or an equivalent; **TEST** = relevant but must be demonstrated/validated before copying; **DEFER** = independent feature or packaging matter outside the initial patch; **N/A** = vendor import or unrelated toolchain adjustment.

## Independent findings while comparing with cu102

1. `unzip60/os2/os2.c` called `DosSetPathInfo` to restore decompressed EA metadata without checking its return code; archive extraction could silently appear successful when EAs were lost. The incremental patch validates native `FEA2LIST` boundaries, names, flags, duplicates, typed symlink EAs, and return status.
2. `zip30/os2/os2zip.c` passed pointers to ZIP 16-bit `z->ext`/`z->cext` into native EA/ACL helpers accepting `size_t*` (32-bit under OW2). The patch uses intermediate `size_t` and checks the 65,535-byte extra-field limit. **This does not by itself guarantee legacy EAs of arbitrary size are preserved.** A larger redesign of EA enumeration/failure propagation is required for that guarantee.
3. Open Watcom exposes a value for `S_IFLNK` but the desired target runtime has no POSIX `readlink()`. The patch uses an independently written native EA reader/resolver (no kLIBC imports), sets an explicit mode tag, and takes the existing link's file data and native EAs with `-y`.
4. An extracted native `SYMLINK` EA must not be mistaken for a generic Unix symlink conversion. Generic `SYMLINKS` macros must remain disabled for OW2 until that separate interoperability feature is designed.
5. Existing Zip `--xattrs` is explicitly unsupported on OS/2 in cu102, and existing UnZip Xtro adapter code is Linux/BSD/Windows-specific. **The incremental build patch does not implement Xtro V1 capture/restore, companion staging, duplicate reconciliation, or cross-platform Xtro symlink restoration.** These remain release blockers for the user's *complete* OS/2 port, not optional enhancements.
6. OS/2 `GetEAs` could construct a dangling `GEA2` next offset when omitting a final `.LONGNAME` EA. The patch links only actually included GEA records and returns errors on failed EA capture.
7. The Open Watcom build exposed a signedness problem in `zipup.c`: `extent` is unsigned on this target. Converting a negative `rdsymlnk()` failure to `extent` before testing would turn `-1` into a huge length and risk an out-of-bounds read. The patch checks the signed result first and bounds the read before conversion.
8. Native OS/2 acceptance is required for file timestamp semantics, actual `SYMLINK` EA layouts, full file/dir EA fidelity, resolver behavior with `@UNIXROOT`, ACLs on LAN systems, and extraction overwrite safety. Build/link and Linux EA mocks cannot establish these outcomes.

## Implementation sequencing after this audit

- **A.** Apply/rebuild this isolated OW2 LX baseline with native link recognition and legacy EA hardening. Get actual ArcaOS acceptance logs before trusting symlink resolution or writing link EAs in production.
- **B.** Implement the OS/2 native Xtro V1 adapter with interface `10`, origin `8`, native flags TLV `10`; support inline and companion paths, early integrity validation, atomic archive publication, independent EA staging, deterministic legacy/Xtro reconciliation and duplicate/conflict errors. Test >64 KiB EAs and metadata collision cases. `--xattrs` must then be enabled for OS/2.
- **C.** Harden path/EA behavior discovered in native acceptance and run multi-platform regressions. Only then call the port fully implemented.
- **D.** Consider `-AS`/`-AC`, broader wildcard grammar, optional library support and `.cmd` utilities as individually tested follow-on patches.

The upstream source is useful as a behavioral specification and bug-history record, **not** a source replacement or a requirement to ship any kLIBC component.
